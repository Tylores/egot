## How It Works

### Handler Method Pattern

Handler methods follow this naming convention:

```go
func (h *Handler) <HTTPMethod><ResourceName>(w http.ResponseWriter, req *http.Request)
```

Examples from Bill service:
```go
func (h *Handler) GETCustomerList(w http.ResponseWriter, req *http.Request)
func (h *Handler) POSTCustomer(w http.ResponseWriter, req *http.Request)
func (h *Handler) PUTCustomer(w http.ResponseWriter, req *http.Request)
func (h *Handler) DELETECustomer(w http.ResponseWriter, req *http.Request)
func (h *Handler) HEADCustomers(w http.ResponseWriter, req *http.Request)
```

### Handler Registration

In `cmd/<Service>/main.go`:

```go
repo := memory.NewRepository()
h := handler.NewHandler(repo)

// Register all handler methods
http.HandleFunc("/", h.GETCustomerList)
http.HandleFunc("/", h.POSTCustomer)
http.HandleFunc("/", h.PUTCustomer)
http.HandleFunc("/", h.DELETECustomer)
http.HandleFunc("/", h.HEADCustomers)
// ... and 65 more handlers for Bill service!
```

## About scaffold-gen

The scaffold-gen tool in cmd/scaffold-gen can ALSO do this automatically via WADL:

### How scaffold-gen Works

1. **Reads WADL Specification**
   ```xml
   <application name="Invoice" port="8025">
     <resources>
       <resource path="/invoices">
         <methods>
           <method name="GETInvoiceList" http_method="GET"/>
           <method name="POSTInvoice" http_method="POST"/>
         </methods>
       </resource>
     </resources>
   </application>
   ```

2. **Generates cmd/<Service>/main.go**
   ```go
   // Auto-generated with proper path registration
   http.HandleFunc("GET /invoices", h.GETInvoiceList)
   http.HandleFunc("POST /invoices", h.POSTInvoice)
   ```

3. **Generates handler stubs**
   ```go
   func (h *Handler) GETInvoiceList(w http.ResponseWriter, req *http.Request) {
       // TODO: implement
   }
   ```

4. **Generates repository**
   - Memory-based storage
   - Get/Set/Delete operations

### Using scaffold-gen

```bash
# For new services with WADL
./cmd/scaffold-gen \
  -wadl ./wadl/invoice-spec.wadl \
  -output .

# Or with SEP2 WADL (special format)
./cmd/scaffold-gen \
  -sep2-wadl ./wadl/sep2-devices.wadl \
  -service Invoice \
  -port 8025 \
  -output .
```

## Two Approaches Compared

### Approach 1: scaffold-gen (For New Services)

**Pros**:
- Generates everything from WADL
- Includes path parameters
- SEP2 WADL support
- Automatic route registration

**Cons**:
- Requires WADL specification
- Generates stubs (need to implement)

**Use when**: Creating new services from specifications

### Approach 2: Handler Script (For Existing Services)

**Pros**:
- Works with existing code
- No WADL needed
- Analyzes real handlers
- Automatic extraction

**Cons**:
- All handlers on "/" (not ideal)
- Need to improve path registration

**Use when**: Existing services without WADL

## Current Implementation

All 15 services use **Approach 2** because:
- ✅ Services already had handlers defined
- ✅ No WADL specifications available
- ✅ Faster to implement
- ✅ No specification maintenance needed

## Future Improvements

### 1. Better Path Registration

Instead of all handlers on "/", extract resource names:

```bash
# In regenerate_cmd_handlers.sh

extract_path_from_method() {
  local method=$1
  
  # GETCustomerList -> /customers
  # POSTOrder -> /orders
  # DELETE... -> extract resource
  
  # Extract resource name (everything after HTTP method)
  local resource="${method#GET}"
  resource="${resource#POST}"
  resource="${resource#PUT}"
  resource="${resource#DELETE}"
  resource="${resource#HEAD}"
  
  # Convert to URL path
  # CustomerList -> /customers
  # Order -> /orders
  echo "/$resource" | tr '[:upper:]' '[:lower:]'
}
```

### 2. Path Parameters

Extract ID parameters from method names:
- `GETCustomerByID` -> `GET /customers/{id}`
- `DELETEOrderByID` -> `DELETE /orders/{id}`

### 3. WADL Generation

Generate WADL from existing handlers for documentation:
- Extract handler methods
- Generate WADL specification
- Use with scaffold-gen for consistency
